JSONSchema2Types — Module
JSONSchema2Types

Generate Julia types from a JSON Schema, together with functions to read and write JSON documents conforming to the schema. See generate_module.

source
JSONSchema2Types.generate_module — Function
generate_module(schema_file, output; root_name, module_name, schemas, split, type_names) -> String

Read the JSON Schema in schema_file (and every schema file it references through $ref) and write to output_file a Julia module defining types for all the objects and enums in the schema, together with functions to read and write JSON documents with them:

  • readjson(T, filename) and fromjson(T, string) parse a JSON document into a value of type T (e.g. the root type), validating it against the schema;
  • writejson(filename, x) and tojson(x) write a value back to JSON;
  • fromdict(T, x) and todict(x) convert from/to parsed JSON values.

The generated module only depends on JSON.jl.

References ($ref) are resolved relative to the file containing them, or by the $id of the loaded schemas. Additional schema files that are only referenced by their $id (e.g. https://example.com/address.schema.json) can be given in schemas. Remote schemas are not downloaded.

The name of the root type is root_name, which defaults to the title of the schema or else to the name of the schema file. The module name defaults to the root type name followed by Types.

By default the whole module is written to the file output. With split = true, output is a directory, and the module is split into several files in it, following the schema files: <module_name>.jl defines the module and includes runtime.jl (the code for reading, writing and validating) and one file per schema file, named after it, with the types defined in that schema file (inline subschemas go with the type containing them). Schema files whose types depend on each other in a cycle share a single file. Load the module by including <module_name>.jl.

Type names are derived from the schema (see the README). Any of them can be chosen with type_names, mapping the location of a subschema, as "file.json#/json/pointer" (or "#/json/pointer" in the root schema file), to the name of its type, e.g. Dict("recipe.json#/definitions/RecipeType/properties/type" => "RecipeKind").

Returns the path of the file defining the module.

Generated modules

Every generated module defines the types of the schema, RootType (the type of the root of the schema), and the following functions and types. They are documented in the generated code, so in the REPL, ?readjson shows their documentation once the module is loaded.

NameDescription
readjson(T, filename)read the JSON file filename into a value of type T
fromjson(T, json)parse the JSON string json into a value of type T
writejson(filename, x; pretty = true)write x as JSON to the file filename
tojson(x; pretty = false)convert x into a JSON string
fromdict(T, x)convert a parsed JSON value into a value of type T
todict(x)convert x into a JSON-compatible value
check_formats!(flag)turn the validation of the format keyword off or on
AbstractSchemaObjectsupertype of the generated structs
AbstractSchemaEnumsupertype of the generated enum types; the value is in the field value
SchemaValidationErrorerror thrown when a value does not conform to the schema
